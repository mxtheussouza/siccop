# Operational coordination platform

An operation-scoped API, web console and Android/iOS field application. Product behavior is defined in [SPEC.md](SPEC.md); engineering rules are in [AGENTS.md](AGENTS.md).

**Phase 01 is in progress.** Dependencies, generated contracts, containers and application builds have not been verified. See [PROGRESS.md](docs/PROGRESS.md) and [LIMITATIONS.md](docs/LIMITATIONS.md). Authentication and operational features are not implemented; the UI explicitly shows that boundary.

## Prerequisites

- Node 24 LTS (`.nvmrc` records the locally observed 24.18.0), pnpm 12.4.2 and uv 0.13.4.
- Python 3.13 (uv can provision it). Managed 3.13.16 is now present on the probed host; uv discovers it without overriding its install directory. The system Python 3.14 must not be used for the API.
- Docker with Compose and a running daemon for real PostGIS/Redis/MinIO integration tests.
- Network access to npm, PyPI, Python distributions and container registries for initial setup.
- Full Xcode for native iOS builds/simulator; Android SDK and an emulator for native Android runs.

## First setup

Both real lock files are present, and `make lock` validates them using cached registry metadata. The application dependencies still require successful downloads. Run the commands below with access to the registries and Docker, review the resolved dependency tree and Expo compatibility, and retain both locks in version control. A passing lock-resolution command does not prove installation or build success.

```sh
make lock
make setup
make infra-up
make migrate
make contracts
make verify
```

`make setup` preserves an existing `.env`, otherwise copies development-only examples with mode `0600`. Infrastructure binds ports to loopback; credentials in `.env.example` are public examples and must never be used outside development. Configuration rejects development credential markers in production. Never commit `.env`.

If Expo reports incompatible native versions, use `pnpm --filter @platform/mobile exec expo install <package>` to select SDK-compatible versions, preserve exact pins in the manifest, refresh `pnpm-lock.yaml`, and record the actually installed results in `docs/VERSIONS.md`.

Run these in separate terminals:

```sh
make api       # http://127.0.0.1:8000/health and /docs
make web       # http://127.0.0.1:3000/login
make mobile-dev # Expo development client; not an Expo Go-only project
```

`/health` is public liveness and does not contact infrastructure. `/ready` is public readiness, returning 200 only if the real DB, Redis and private storage bucket are accessible, otherwise a sanitized 503 problem response. These two infrastructure endpoints deliberately have no domain authorization. Operational endpoints and authorization arrive in Phase 02. Disable Uvicorn access logs as in `make api` to avoid logging query parameters.

Settings are loaded from `.env` in the current directory. `make migrate` runs from `apps/api`, so the migration environment reads the root `.env` explicitly. `API_UPSTREAM` is used by Next.js for same-origin `/api/*` proxying. No API token is persisted by either scaffold. Mobile device URLs must use a reachable development host instead of device-local `localhost`; location permissions are not requested by this scaffold.

## Commands and verification

| Command | Behavior |
|---|---|
| `make lock` | Resolve Python/JS dependencies into real lock files |
| `make setup` | Preserve/create local env, install locked dependencies, check Expo compatibility |
| `make infra-up` / `infra-down` | Start healthy local infrastructure / stop it without deleting volumes |
| `make migrate` | Apply the linear Alembic history; Phase 01 enables PostGIS only |
| `make seed` | Fail explicitly with `NOT_IMPLEMENTED`; domain development seed is Phase 02; refuses production |
| `make worker` | Start the configured Dramatiq process; no domain actors until Phase 06 |
| `make mobile` | Export Android and iOS JS bundles without signing credentials |
| `make mobile-dev` | Start Metro for a development build |
| `pnpm --filter @platform/mobile build` | Export Android and iOS JS bundles; does not constitute a native build |
| `make test` | API unit tests, web/mobile unit tests, package tests and tooling tests |
| `make test-integration` | Run real Testcontainers PostGIS/Redis/MinIO tests; fails with `NOT RUN` if Docker is unavailable |
| `make lint` / `format` / `format-check` / `typecheck` / `build` | Shared gate stages |
| `make contracts` / `contracts-check` | Export FastAPI OpenAPI and TS types / compare regenerated bytes to tracked artifacts |
| `make verify` | Fail at first error: format → lint → typecheck → unit → integration → build, then contract freshness |
| `make phase-check` | Check source inventory, contract freshness and Expo public config |

The real integration test `test_postgis_migration_and_readiness_redis_outage` migrates a PostGIS container, checks the extension and revision, confirms `/ready` 200, stops Redis, confirms `/ready` 503 and `/health` 200. Unit readiness tests inject a probe to test HTTP mapping only; they do not claim PostgreSQL behavior. No database substitutes are used.

Contracts are exported without connecting to infrastructure. Missing/stale artifacts fail CI. API types must never be handwritten. Infrastructure and generated files cannot be called verified until the network-dependent checks actually run.

Optional profiles:

```sh
docker compose --env-file .env --profile worker up -d --build --wait
docker compose --env-file .env --profile monitoring up -d --wait
```

Grafana is at `http://127.0.0.1:3001`, Prometheus at `http://127.0.0.1:9090`, MinIO console at `http://127.0.0.1:9001`. Monitoring currently observes Prometheus itself; API instrumentation belongs to Phase 13. MinIO bootstrap creates a private bucket and removes anonymous access. Container health does not prove future domain jobs work.

## Platform notes

- **macOS:** GNU-compatible Make commands work with the system Make. Docker Desktop must be running. This environment has Command Line Tools only; full Xcode/simulator installation is still required. Some PostGIS image tags may require Docker's amd64 emulation on Apple Silicon; verify the selected image before claiming infrastructure success.
- **Linux:** install Make, a supported Node/uv toolchain, and Docker with daemon access. Android needs an SDK/emulator. Linux cannot perform a native iOS build; an iOS JS bundle or prebuild is not iOS runtime evidence.
- **Windows:** use WSL2 with Make, Node, uv and Docker Desktop WSL integration. Run the checkout and all tooling inside the same WSL environment. PowerShell is not the recipe shell; native iOS builds require macOS.

No Git repository was present in the supplied directory. Initialize/review version control before committing lock files and generated artifacts; no commits have been created by this session.
